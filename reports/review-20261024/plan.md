## 0. 一页结论

1. **这套系统已经能"想起东西"，但还不会"只想起对的东西"。** 抽查 72 个注入块：有用 9（12.5%）、弱相关 36（50%）、无关 22（30.6%）、有害 5（6.9%）。
2. **唯一被证明有效的层是卡片（written memory）**：9 条有用条目全部来自卡片，覆盖财务账、网络约束、端侧选型、重启事故等跨会话事实。transcript excerpt 的有用率接近 0，却占 0.12 区间 39% 的条目。
3. **最近三次改造，两次方向正确、一次没有达标**：
   - 0.11.0 判定层 + 闸门 3→0：把 10-08～10-12 的零注入救回 inject/armed 26.4%，是正确改造；
   - 0.12.0 sourceKind 白名单：索引侧 audit PASS（注入行 0，user 行 2764 全带来源），正确；
   - 10-22 闸门放宽 0→−1.0/−1.5：pass 率 59.7%→75.0%，但 inject/armed 26.4%→**24.5%**，没有解决体感；同日 judge threshold 0.5→0.4 是**空转**（无样本落在 [0.4,0.5)）。
4. **10-22 之后出现新的静默失败**：judge fallback 占比 5.4%→**16.8%**（10-23 有 21 次，耗时 2.5–5.3s，**不是 15s 超时**），fallback 一律 skip = 静默不召回。
5. **质量瓶颈已从"要不要召回"转移到"召回什么"**：卡片降级地板 0.35 在当前 EG2 向量空间下恒真（随机 token 8/8 通过，cosine 下界约 0.58）；transcript 无注入侧内容过滤、无 self-recall 排除、57–68% 条目被截断在 330 字符。
6. **观测与工程底座缺失**：inject 打点不记内容身份；`npm test` 本地恒红 4 项（50/54）；web profile 仍跑 gate=3 无 judge 的旧配置；profile 用 symlink 直连 HEAD，无版本钉住与回滚点。

## 3. 根因

1. **同一套分数裁决两类不同内容**。card 是策展内容（cosine/rerank 有意义），transcript 是原始文本（需要长度/形态/来源/自召回等质量门槛）。现在两类共用 `floorForAge` 与降级地板，导致卡片在降级时恒过（D1），transcript 碎片直接漏进注入（D5）。
2. **降级方向反了**。rerank 失败/候选 <2 时，卡片改用恒真的 0.35、单元改用 rrfFloor（最宽松档），与 README 的 "err toward missing a memory rather than inventing one" 相反（D2）。
3. **截断策略自相矛盾**。`selectForInjection` 注释写"截断的记忆是错的记忆"，实现却把条目切到 ≤330 字符且不标注（57–68%）。
4. **没有质量闭环**。所有验收都看"注入次数/通过率"，没有"注入是否被使用、是否相关"的指标；10-22 放宽后无法判断效果，只能靠体感。
5. **部署不可回滚**。profile 的 node_modules/dsh-g-memory 是 symlink 指向仓库，重启即加载 HEAD；10-22 的代码与配置改动都没有版本号/CHANGELOG，出问题只能靠 git 手工回退。
6. **静默失败仍在**。judge fallback 一律 skip；doctor 对 fallback 只算 warning（`process.exit(badCount>0 ? 1 : 0)`，D10），不会被当成故障。

## 6. 风险与回滚

- **收紧卡片地板会降低召回**：先离线用 184 张卡 + 负样本集校准，定分位数再上线；保留旧值作 env 覆盖。
- **transcript 过滤可能误杀短而有价值的片段**：只按形态（JSON/单行/路径/日志清单）过滤，不按长度一刀切；长度阈值先 60 字符，观察一周。
- **judge fallback 依赖端点稳定性**：即使根因修不了，也要把 fire 后失败降级为 hint 而不是静默。
- **所有 P0 改动都要能一键回退**：pre-release 快照 + profile 配置备份（参照 10-22 的 `.bak-before-recall-tune` 做法）。

## 7. 附带发现（本轮新增，需跟进）

1. **注入条目的时间按 UTC 渲染，比本地时间早 8 小时**。`lib/inject.mjs:220` 与 `lib/cards.mjs:258/470` 用 `toISOString()` 生成 `when`，而注入块是给人/模型读的本地时间语境；recall-evaluator 的"原始 age 最小恰为 8.0h"就是该缺陷指纹。修复：用本地时区格式化（或 ISO 带偏移），并在 stats 中记录原始 epoch。
2. **治理层分支在真实数据里从未出现**。639 条注入条目只出现 3 种 provenance（written memory / transcript excerpt / synthesized answer）；代码里的 `unverifiable`、`authored change`、`superseded`、`retired`、`orphaned` 一次都没触发（`lib/inject.mjs:244-277`）。需要核对：`orphaned`/`editedByHuman` 是否从赋值到渲染的链路断掉，还是 184 张卡里确实没有非 active 卡进入过注入。
3. **hint 打点 165 次、日志落地仅 36 次（22%）**。可能是重复抑制/未到 step 就被覆盖/未真正投递。若属后者，它是与 judge fallback 同类的静默失败，应纳入 P1-1 一起查。
4. **早期 stats 不可用于评价注入量**：0.12 起 inject 打点与日志逐日 1:1，但 09-23～10-02 的口径不一致（多记/漏记）。复盘历史时以日志落地为准。
